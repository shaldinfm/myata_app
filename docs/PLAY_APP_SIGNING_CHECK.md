# Проверка Play App Signing — что нужно от владельца

> В этом документе нет и не должно быть ни одного секретного значения.
> Скриншоты перед отправкой проверьте на отсутствие паролей и алиасов.

Нужно для закрытия [issue #2](https://github.com/shaldinfm/myata_app/issues/2).
Релиз API 36 этой проверкой **не блокируется** — работа продолжается параллельно.

## 1. Где открыть

Google Play Console → выберите приложение **Радио Мята**
(`dlinemedia.radioplayer.myata`) → в левом меню
**Test and release → Setup → App integrity** → вкладка **App signing**.

Прямая ссылка вида:
`https://play.google.com/console/u/0/developers/<developer-id>/app/<app-id>/keymanagement`

## 2. Как понять, включён ли Play App Signing

| Что видно на странице | Что это значит |
|---|---|
| Блоки **«App signing key certificate»** и **«Upload key certificate»** (два разных сертификата, SHA-256 у каждого) | **Play App Signing включён.** Ключ подписи хранится у Google, локальный `.jks` — это только upload key |
| Только один сертификат, без раздела про upload key | Play App Signing, скорее всего, **включён со старой схемой** (upload key = app signing key) |
| Кнопка/баннер **«Use Play App Signing»**, предложение загрузить ключ | Play App Signing **выключен** |

## 3. Что прислать

1. Скриншот вкладки **App signing** целиком.
2. Ответ одной строкой: два сертификата на странице или один.
3. Если есть раздел **Upload key certificate** — просто подтвердите его наличие.

Присылать **не нужно**: файл `.jks`, пароли, алиас, содержимое `keystore.properties`.
Сертификаты и их SHA-256 — публичные данные, их показывать безопасно.

## 4. Почему ключ сейчас не ротируется

Решение владельца от 05.08.2026 — **ротацию не делать**. Основания:

- файл `.jks` **никогда не публиковался в Git** (проверено по всей истории репозитория:
  ни одного добавления `*.jks` / `*.keystore`);
- файл `.jks` **никогда никому не передавался**;
- приложение **не публиковалось** в RuStore и других магазинах;
- в публичную историю попали только **пароли и алиас** (коммит `50b897d`,
  значения — `<redacted>`), а без самого файла keystore подписать сборку ими нельзя;
- главный приоритет до 31.08.2026 — гарантированный релиз API 36.

Что при этом уже сделано и проверено на ветке `release/api36-2026`:

- в отслеживаемых файлах нет ни одного литерального signing-значения;
- `.gitignore` закрывает `keystore.properties`, `*.jks`, `*.keystore`;
- `keystore.properties.example` содержит только имена ключей, без значений;
- `bundleRelease` без локального `keystore.properties` падает с понятным
  сообщением и не выпускает неподписанный артефакт.

## 5. Что решается после ответа

- **Play App Signing включён** → ротация upload key делается штатно через
  Play Console, без риска для приложения. Планируется отдельной задачей после релиза.
- **Play App Signing выключен** → нужно отдельное решение владельца; риск выше,
  так как локальный ключ является единственным.

Отдельно, вне issue #2, остаются два секрета в публичной истории и в текущем коде:
Last.fm API key в `ArtworkRepository` и открытый Apps Script endpoint в
`FeedbackRepository` (значения — `<redacted>`). Их замена запланирована отдельной
задачей и не входит в релиз API 36.
