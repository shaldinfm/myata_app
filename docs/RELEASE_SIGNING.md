# Релизная подпись MyataRadio

> В этом документе нет и не должно быть ни одного секретного значения.
> Пароли, алиасы и имена keystore-файлов никогда не коммитятся и не цитируются в issue/PR/логах.

## Как устроена подпись

Релизная подпись читается из файла **`keystore.properties`** в корне проекта:

- файл **не отслеживается git** (`.gitignore`) и существует только локально у владельца;
- шаблон — `keystore.properties.example` (только имена ключей, без значений);
- ключи: `storeFile`, `storePassword`, `keyAlias`, `keyPassword`;
- `storeFile` — путь к keystore (абсолютный или относительно корня проекта); сам keystore-файл тоже никогда не попадает в репозиторий.

> **Про слэши в `storeFile`.** Файл читается через `java.util.Properties`, который
> трактует `\` как escape-символ и молча съедает одинарные обратные слэши. На Windows
> путь нужно писать через прямые слэши (`D:/keys/...`) или удваивать обратные
> (`D:\\keys\\...`), иначе путь не разрешится.

## Сборки

| Сборка | Требования |
|---|---|
| `./gradlew assembleDebug` | Ничего секретного не нужно. Работает из свежего клона у любого разработчика/агента |
| `./gradlew assembleRelease` / `bundleRelease` | Требует локальный `keystore.properties` **и** существующий keystore по указанному в нём пути. Если чего-то не хватает — сборка падает с явной ошибкой (без вывода значений) |

Проверка выполняется на этапе готовности task graph, то есть **до запуска любых
задач**. Поэтому при недоступном signing config сборка не создаёт ни `.aab`, ни
`.apk` — в `app/build/outputs/` не появляется ничего нового. Если файл там уже
лежит, он остался от прежнего прогона; перед релизной сборкой каталог стоит
чистить (`./gradlew clean`), чтобы не спутать старый артефакт с новым.

## Правила обращения с секретами

1. `keystore.properties`, `*.jks`, `*.keystore` — никогда не коммитить (закрыто `.gitignore`).
2. Значения подписи не печатать: ни в Gradle-логах, ни в CI, ни в issue/PR, ни в чатах. При необходимости сослаться — использовать `<redacted>`.
3. Готовые артефакты (`*.apk`, `*.aab`), логи сборки и подписи (`build_log*.txt`, `signed_bundle_log*.txt`, `*.logcat`) в git не попадают.
4. Релиз и загрузка в стор — только владелец, по явному решению (GO).

## ⚠️ История репозитория (важно)

Перевод подписи на `keystore.properties` очищает **только текущее дерево**. В публичной git-истории репозитория ранее были закоммичены значения релизной подписи, и любой существующий клон их сохраняет. Поэтому:

- утёкшие значения следует считать скомпрометированными безвозвратно;
- **ротация ключей** (через консоль стора), **перевод репозитория в private** и/или **переписывание истории** (BFG / `git filter-repo`) — отдельные решения владельца; данный документ и связанный PR их **не выполняют**;
- статус этих решений отслеживается в issue #2.
