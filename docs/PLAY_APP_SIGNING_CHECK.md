# Play App Signing — подтверждённый статус

> В этом документе нет и не должно быть ни одного секретного значения.
> Отпечатки сертификатов — публичные данные, их приводить безопасно.
> Пароли, алиас, путь к `.jks` и содержимое `keystore.properties` — никогда.

**Статус: подтверждён владельцем 08.08.2026 по Google Play Console.
[Issue #2](https://github.com/shaldinfm/myata_app/issues/2) закрыт.**

## 1. Что установлено

**Play App Signing включён.**

| Ключ | Где хранится | SHA-256 |
|---|---|---|
| App Signing Key | у Google, разработчику недоступен | `E5:B0:0F:C8:3C:2D:96:ED:4C:C2:2A:43:0F:68:BC:11:BD:60:E5:DB:85:17:6F:68:B9:14:07:B7:37:6F:88:71` |
| Upload Key | локальный `.jks` владельца, вне репозитория | `83:09:01:4E:8A:7F:69:0F:FD:A9:54:CB:78:9C:44:21:6B:BF:91:7F:71:0B:7D:EA:A9:35:D0:73:1B:A2:22:5A` |

Из этого следует главное: **существующий `.jks` — это upload key, а не ключ подписи приложения.**
Ключ, которым Google подписывает то, что получают устройства, у нас никогда не был
и скомпрометирован быть не может.

## 2. Сверка с релизным артефактом

Release AAB, собранный на ветке `release/api36-2026`
(`app/build/outputs/bundle/release/app-release.aab`, versionCode 202611):

- `jarsigner -verify` → `jar verified`;
- сертификат подписи AAB **совпадает с Upload Key** (SHA-256 выше, побайтово);
- сертификат подписи AAB **отличается** от App Signing Key.

Это ожидаемое и правильное поведение: разработчик подписывает upload-ключом,
Play принимает загрузку по нему и переподписывает бандл app signing key.

## 3. Ротация upload key сейчас не требуется

Решение владельца от 08.08.2026. Основания:

- файл `.jks` **никогда не был в Git** — проверено по всей истории репозитория,
  ни одного добавления `*.jks` / `*.keystore`;
- файл `.jks` **никогда никому не передавался**;
- приложение **не публиковалось** в RuStore и других магазинах;
- в публичную историю попали только **пароли и алиас** (коммит `50b897d`,
  значения — `<redacted>`); без самого файла keystore подписать ими ничего нельзя;
- Play App Signing включён, поэтому даже при компрометации upload key он меняется
  штатно через Play Console, без риска для приложения и уже установленных копий.

Очистка git history сейчас не выполняется, App Signing Key не трогаем,
репозиторий остаётся публичным — осознанное принятие риска, зафиксировано в issue #2.

## 4. Где перепроверить

Google Play Console → **Радио Мята** (`dlinemedia.radioplayer.myata`) →
**Test and release → Setup → App integrity** → вкладка **App signing**.

Признак включённого Play App Signing — два отдельных блока,
**App signing key certificate** и **Upload key certificate**, у каждого свой SHA-256.

## 5. Что защищает репозиторий

Проверено на ветке `release/api36-2026`:

- в отслеживаемых файлах нет ни одного литерального signing-значения —
  конфиг читается из неотслеживаемого `keystore.properties`;
- `.gitignore` закрывает `keystore.properties`, `*.jks`, `*.keystore`, `*.aab`, `*.apk`;
- `keystore.properties` не отслеживается и ни разу не коммитился;
- `keystore.properties.example` содержит только имена ключей, без значений;
- в собранном AAB нет ни signing-значений, ни keystore, ни properties-файлов.

⚠️ Уточнение к `RELEASE_SIGNING.md`: гард на отсутствие `keystore.properties`
срабатывает **после** того, как неподписанный `.aab` уже создан на диске —
он висит на `bundleRelease`, а файл производит `packageReleaseBundle`.
**Подписанный** артефакт без локального конфига получить по-прежнему нельзя,
и неподписанный в git не попадает, но гард стоит перевесить:
[issue #10](https://github.com/shaldinfm/myata_app/issues/10).

## 7. Перед загрузкой в Play

1. Прогнать сборку на реальном устройстве — эмулятор не покрывает Bluetooth-гарнитуру,
   входящий звонок, чужой audio focus и экран блокировки.
2. Загружать в **Internal Testing**, не в production.
3. Загрузку выполняет только владелец.
